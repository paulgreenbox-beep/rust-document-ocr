# Windows dependency notice reconciliation

This is an addendum to the original candidate, not a replacement manifest. [Component matrix](COMPONENT_MATRIX.json) binds the review to the exact executable, candidate manifest, Cargo.lock and link-input receipt. [Additional recipient notices](NOTICE.md) can be copied with the complete `notices/` subtree into `licenses/windows-dependencies/` **after** owner review. Keep existing candidate notices and bind the new files to their component rows in a new manifest. No current runtime or manifest was modified.

## What the review covers

- 246 recorded component rows: 225 Rust-package rows (including the project and the patched decoder), 16 vcpkg rows, and 5 runtime payload/notice rows. All 223 registry archives matched both Cargo.lock and the candidate inventory; their license declarations agreed. All 445 distinct existing notice paths in the manifest matched the packaged files' recorded sizes and SHA-256.
- 170 Rust package rows and 16 vcpkg rows have matching linker inputs. Another 55 Rust rows are in the selected dependency graph without an individually matched input. 13 additional Rust toolchain archives match the Rust 1.97.1 sysroot. There are also 17 MSVC/SDK library-input occurrences and nine unscanned temporary-object inputs. The absence of an individual matching input does not prove absence of generated or inlined code. Inclusion as a link input does not prove every member was retained.
- Ten registry rows had no bound notice in the candidate, and neither did EG79. The matrix explicitly maps the proposed replacement texts for each row; the old empty lists are preserved as historical evidence. Other rows with a license expression and notice are inventoried, not independently certified clear. Native provenance and redistribution authorizations remain separate.

Keep the libwebp 1.6.0 notice, which already contains [COPYING](https://github.com/webmproject/libwebp/blob/v1.6.0/COPYING) and [PATENTS](https://github.com/webmproject/libwebp/blob/v1.6.0/PATENTS). Its grant is not a HEVC patent grant. For [zstd 1.5.7](https://github.com/facebook/zstd/tree/v1.5.7), retain the existing texts and have the publisher record the selected license option (BSD-3-Clause is the proposed option). For libarchive BLAKE2, retain the extracted text with its offered Apache-2.0 option; record the actual election and include the applicable full license.
