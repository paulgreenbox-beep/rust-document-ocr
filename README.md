# Rust Document OCR

Rust Document OCR is a local, CPU-first document pipeline written in Rust. The
Cargo package and library crate are named `ocr-pipeline`, version `0.1.0`.
This documentation does not claim a stable `1.0` release.

The engine reads PDF, raster image, TIFF, HEIF, and DjVu inputs, extracts usable
PDF text where available, runs Tesseract when OCR is needed, detects table
geometry, and exports JSON, DOCX, and XLSX files. It is a command-line program
and Rust library; it does not provide an HTTP service or hosted API.

## Current scope

- The CPU pipeline has a bounded page-worker pool. Its default is four workers;
  PDFium access remains serialized.
- Cargo's default feature set is empty. A default build does not process real
  documents. Enable `native` for PDFium, Tesseract, and the local input
  decoders, including raster images, TIFF, WebP, HEIF, and DjVu.
- The validated release target is Windows x64. Other operating systems have not
  been validated for this release.
- No executable, native runtime DLL, traineddata file, or model weights are
  included in this source package. Native processing requires locally supplied
  runtime components and language data.
- OCR is local. Document content is not sent to a cloud service by this engine.

## Results and table semantics

A successful CLI run writes these files into a new output directory:

- `result.v1.json`: versioned JSON result envelope (schema version 1);
- `result.json`: compatibility JSON document;
- `result.docx`: extracted text and supported title-block projection;
- `result.xlsx`: detected tables.

Table structure and subject-matter classification are separate. The structural
`kind` remains `data_table`, `title_block`, or `unknown`. Additive semantic
fields can report a probable table type, header rows, column roles, confidence
scores, and rule evidence. The classifier uses local deterministic heuristics;
it does not change recognized cell text or invent missing values. Scores are
signals for review, not correctness guarantees.

The library also exposes a PDF region-processing API. It is an in-process Rust
API, not a CLI endpoint or network service.

## Build and run

For the separately gated Windows portable candidate, see
[PORTABLE_WINDOWS.md](docs/PORTABLE_WINDOWS.md). This source repository does
not imply that a redistributable binary ZIP has been cleared or published.

Install the build tools and native runtime dependencies described in
[CONTRIBUTING.md](CONTRIBUTING.md). Supply a PDFium API 7881 DLL for PDF input
and Tesseract traineddata for the requested languages. The example paths below
are local placeholders; the source package does not contain those files.

```powershell
$pdfium = (Resolve-Path './local-runtime/pdfium/7881/bin/pdfium.dll').Path
$tessdata = (Resolve-Path './local-runtime/tessdata').Path

cargo run --locked --features native --bin ocr-pipeline -- `
  --input './examples/documents/synthetic-text-table.pdf' `
  --output-dir './target/ocr-example-output' `
  --pdfium-dll $pdfium `
  --tessdata-path $tessdata `
  --languages 'rus+eng'
```

The output directory must not already exist. The published sample is a
[synthetic input document](examples/documents/synthetic-text-table.pdf); its
[recorded JSON result](examples/output/result.v1.json) is generated by running
the engine.

See [OCR_PIPELINE.md](docs/OCR_PIPELINE.md) for the complete CLI and library
reference, [ARCHITECTURE.md](docs/ARCHITECTURE.md) for the processing design,
and [EXPERIMENTAL_FEATURES.md](docs/EXPERIMENTAL_FEATURES.md) for opt-in
features and known limits.

## Configuration and public examples

The real CLI accepts arguments; it does not load an invented configuration
file format. [config.example.ps1](examples/config.example.ps1) is a safe
PowerShell wrapper with relative paths. Language data is external: normal
`rus+eng` recognition needs `rus.traineddata` and `eng.traineddata`;
explicit Chinese routing needs `chi_sim.traineddata` as well. Missing runtime
or required language data produces an error, not fabricated OCR results.

The [image-only sample](examples/documents/synthetic-raster.pdf) and its
[recorded result](examples/output/raster-result.v1.json) exercise Tesseract.
The text/table sample exercises native text plus grid geometry. See
[fixture provenance and excluded tests](docs/FIXTURE_PROVENANCE.md).

## Development and limitations

Run `cargo fetch --locked` before the offline commands in CONTRIBUTING.
Public CI checks formatting, default-feature compilation, tests and Clippy;
it does not install native runtimes or certify OCR accuracy. Native tests are
also checked locally with separately supplied runtimes. Existing frozen style
expectations are documented in [LINT_BASELINE.md](docs/LINT_BASELINE.md).

Geometry detection and text recognition can fail independently. Complex merges,
borderless tables, multi-line descriptions, small symbols, residual grid lines
and ambiguous technical values remain limitations. Confidence values are review
signals, not proof of a correct transcription. No universal CER/WER or accuracy
claim is made from synthetic examples.

Native installation and test-runtime instructions: [INSTALL_WINDOWS.md](docs/INSTALL_WINDOWS.md).
